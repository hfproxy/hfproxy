Cache rules

Cache limits

Each limit works on its own; 0 turns it off. When a limit is exceeded, eviction brings usage back to the target below so it does not run at every pass. Pinned files and repositories published on the proxy are never removed.

Eviction strategy

Every download moves the file to the front of one queue; when room is needed, the file at the back goes. Simple and predictable. A 60 GiB file downloaded once three days ago outlives a 2 MiB file downloaded fifty times four days ago, and someone trying a model once pushes useful files out.

Like LRU, but how long a file has been idle is weighed against how long it takes to fetch again. A 30 GiB shard that took twenty minutes to arrive may stay idle longer than a config.json that comes back in a second. The cost is the measured duration of the file's last fetch from the Hub; files cached before this version are priced from their size with the estimates below.

score = weight × ln(cost) − ln(idle time); the lowest score goes first } @case ('gdsf') {

GreedyDual-Size-Frequency, the policy of Squid and of CDN caches. A file is worth frequency × cost ÷ size: a small file that is often downloaded is worth a lot per byte, a large shard downloaded once is worth little. Best hit rate counted in files, but large shards are sacrificed first; avoid it when those are exactly what costs bandwidth. Frequency fades with the half-life.

score = ln(frequency) + ln(cost) − ln(size) } @case ('lfu') {

Every download adds one to the file's counter, and the counter halves at every half-life. The lowest counter goes first. The HEAD requests clients send to check a file do not count. Size and cost are ignored, and a file that was popular last month stays until the half-life has worn its counter down.

Whether a file is stored at all the first time a client asks for it. Many models are tried once and never loaded again; storing them evicts files that are still in use. A file that is not stored is still served, streamed from the Hub. Preloads and files under the minimum size are always stored.
